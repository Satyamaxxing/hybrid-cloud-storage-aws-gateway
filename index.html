Figure 3.1: Hybrid Storage Sync Workflow

1. Identify Data: On-premises file shares to be synced.
2. Create S3 Bucket: Enable versioning, KMS encryption & IAM least-privilege role.
3. Deploy Gateway Appliance: ESXi / Hyper-V / KVM or Amazon EC2 instance.
4. Activate & Allocate Cache: 150+ GiB NVMe disk for hot cache & upload buffer.
5. Create File Share & Mount: NFS (Linux) or SMB (Windows) with CIDR firewall.
6. Auto-Sync & Monitor: Asynchronous upload over TLS 1.3, CloudWatch & S3 lifecycle.

College Viva Voce Q&A Cheat Sheet (For Evaluation & Defense)

Q1: What are the 4 types of AWS Storage Gateway?

1. S3 File Gateway (NFS/SMB to S3 objects - our project)
2. FSx File Gateway (SMB to FSx Windows File Server)
3. Volume Gateway (iSCSI block storage backed by EBS)
4. Tape Gateway (Virtual Tape Library to S3 Glacier)

Q2: Why are writes asynchronous and how does caching help?

Writes are acknowledged instantly by the local SSD cache disk (0.9ms latency), giving local users fast LAN performance. The upload buffer queues and asynchronously uploads chunks to S3 over TLS 1.3 without blocking client applications.

Q3: How do direct S3 changes sync back to on-prem users?

Using the RefreshCache API call or automated EventBridge triggers. The gateway queries S3 inventory, updates its local metadata index, and presents remote changes to NFS/SMB clients.

Q4: How does AI integrate into this hybrid storage model?

Since files are stored as plain S3 objects (not proprietary file system blocks), AWS AI services like Amazon Macie can inspect them for sensitive data leaks, Amazon Textract extracts document OCR, and Amazon Rekognition classifies images.
